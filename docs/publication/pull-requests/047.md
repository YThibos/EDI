# EDI-51 Show board-bound decisions as one line under their board and refuse re-asking an answered card

## What it changes

The commits, in order:

- Refuse a board card whose title an answered decision of its task already carries
- Show a board-bound decision as one line under its board on every surface
- Start the oddly named process through a link so no other start can hold its file open
- Hang a wrapped board decision title past its number on the console
- List a listening board's bound decisions under it, even with no questions
- Align board skill and backlog doc with board-bound decisions
- Fixed it: a listening board that asks no questions of its own but binds an open decision no longer says "0 questions waiting" on any surface. The rule behind it: a board that asks no questions never claims a question count, and is not counted as an open item on its own. The decisions it binds are what wait on the captain. Where the line changed: - **Report, sitrep and return brief** (`WaitingWords.board`): the line now reads "Board for X: waiting at <link>" when the board has no questions. Boards with questions still read "N questions waiting at <link>". - **Session-start digest** (`SessionStartDigestText.boardLine`): "board task <link>" instead of "0 questions at <link>". - **Console waiting list** (`waiting-list.ts`, `boardSummary`): the sub-line shows only the projects instead of "0 questions waiting · projects". Where the count changed (a board with no questions counts only its bound decisions, not 1 + decisions): - `DecisionZone.BoardQuestions.open()`: the "N open" count in the report and sitrep. - `WaitingBoard.count()`: used by `WaitingOnTheCaptain.count`, which the digest uses. - The console sitrep page's `openOnBoards`. Before the change, a board with no questions and one bound decision gave "2 open" over a single decision line. Tests: - The AT-19 test (`DecisionsAndReportingTest`) used to pin "0 questions waiting" and "2 open". It now pins "waiting at" and "1 open", and also covers the return brief and digest lines for that case. - `FleetSnapshotQueryTest` now expects a count of 1 instead of 2. - Two new console specs: the waiting-list sub-line for a board with no questions, and the sitrep page count. - The two decision records (`captain-report.md`, `fleet-snapshot.md`) now state the counting rule. Verification: `./mvnw -B -ntp verify` passed (1,201 core and 74 command tests) and `npm test` in `edi-console` passed (36 tests). Both ran before the final two-line edit to the decision records, so that edit is the only change not covered by a run. Not changed: the return brief's "Needs your decision (N)" heading counts printed lines, not open items, so a board with no questions and one decision still shows "(2)" there. That line count also drives its "(+N more)" cut-off, so I left it alone
