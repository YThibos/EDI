# EDI-23 Follow a task's merge request whatever order things happen in

## What it changes

The commits, in order:

- Follow a task's merge request whatever order things happen in
- Refresh accepted deliveries and follow successors of closed requests
- Give the closed-delivery rule one owner in DeliveryRecords
- Say delivery watches every open merge request
- Accept only the task's own merges; skip unfollowable tasks
- Own merged requests by merge time since dispatch
- Fail forge reads on unreadable merge times
- Choose the latest owned merge regardless of forge order

## How it was verified

The repository's build and tests, `./mvnw verify`, passed before the merge, with the native build where the change could reach the native image, and CI ran on the pull request.
