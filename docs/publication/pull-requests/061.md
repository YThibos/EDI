# EDI-102 Ship EDI's own helloedi launcher, updating EDI when the installed build lacks origin/main

## What it changes

The commits, in order:

- Ship EDI's own helloedi, updating EDI when the installed build is not origin/main
- Update EDI only when the installed build lacks origin/main, recording it last
- Name helloedi and the recorded build in the update skill
- Define the build record step below the skills step it follows
- Place the installed executables in EDI_BIN in core-lifecycle

## How it was verified

The repository's build and tests, `./mvnw verify`, passed before the merge, with the native build where the change could reach the native image, and CI ran on the pull request.
