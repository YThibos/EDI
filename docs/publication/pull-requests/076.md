# EDI-81 Learnings name their ticket

## What it changes

A learning in the captain's memory either is a dated fact or names the ticket that removes it, and EDI itself says when such a ticket has landed or does not exist, so the primary no longer notices expired workarounds by chance.

The commits, in order:

- Ask how the digest counts workarounds keyed on JIRA
- Record the captain's answer: the digest counts workarounds from the store
- Read a captured log event without a message as an empty line
- Flag expired and unticketed workarounds in the stow list and the digest
- Mark the item delivered

## How it was verified

The repository's build and tests, `./mvnw verify`, passed before the merge, with the native build where the change could reach the native image, and CI ran on the pull request.
