# EDI-120 WaitControllerTest no longer races its own wake, and no test core opens the captain's browser

## What it changes

`WaitControllerTest` no longer races its own wake, the production code is checked for the same race, and no test can ever start the real browser.

The commits, in order:

- Let the held-wait test accept a wake its first look delivers
- Record the browser in every test core instead of opening the captain's
- Record that every Spring test core records its browser
- Give the command's tests a silent SLF4J provider
- Mark the item delivered in the backlog
- Leave logback's configuration to logback in the core's test JVMs
- Hand java.util.logging to SLF4J in the core's test JVMs
- Draw the synthetic AWS key's characters without repetition

## How it was verified

The repository's build and tests, `./mvnw verify`, passed before the merge, with the native build where the change could reach the native image, and CI ran on the pull request.
