# EDI-16 Keep AT-38 and the full suite inside the test timeout

## What it changes

The commits, in order:

- Keep AT-38 and the full suite inside the test timeout
- Ci-1 (Native build and smoke test) was a flaky test, not a broken build or a broken native smoke test. In the JVM test run of that job, `BeyondTheInvariantsTest.theImportWritesWhatItsDryRunPlanned` failed at line 217 ("the old home after the import"). The only difference between the two snapshots was `projects/harbour/.git/objects/maintenance.lock`, which appeared in the "before" snapshot and was gone afterwards. Root cause: `FixtureRepository.commit` runs `git commit`. On CI's git 2.55, that starts `git maintenance run --auto` as a detached background process, which briefly holds `objects/maintenance.lock` in the fixture repository. The test snapshots the old home straight after creating its clones, so the snapshot sometimes caught the lock file. The import itself never writes to the old home. Locally (git 2.43, which runs auto-maintenance in the foreground) the test passed six out of six times, so the race only shows on CI's newer git. Invariant violated: a git command a test runs in a fixture repository must finish all its work before it returns, so the test can read that repository without racing a background process. Places where it must hold: every repository `FixtureRepository` creates, which is `initialise` (git init) and `clonedInto` (git clone). Setting it in the repository's own configuration covers both the fixture's own git calls and the git that EDI's adapters run against those repositories. That matches the decision record ("a test that needs a git setting gives it through the repository's own configuration"). Fix (`edi-core/src/test/java/io/github/ythibos/edi/testing/FixtureRepository.java`): `initialise` and `clonedInto` now both end with a private `withoutBackgroundMaintenance()` helper that sets `maintenance.auto=false` through the existing `configure` method. No other change. Verification: `mise exec -- ./mvnw -B -q verify` passed (exit 0, no failures). The native build was not rerun, because the change touches only JVM test fixture code and no Spring configuration, reflection, resources or the command

## How it was verified

The repository's build and tests, `./mvnw verify`, passed before the merge, with the native build where the change could reach the native image, and CI ran on the pull request.
