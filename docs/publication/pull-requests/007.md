# EDI-6 Add supervision and recovery: primary and standby, edi wait, health rules, usage limits, relaunch and the outage hold list (slice S4)

## What it changes

The commits, in order:

- Supervise workers and the primary from hooks and recover from outages
- Test supervision, waking, usage limits and recovery from the domain to the command
- Record the S4 decisions and prove recovery on the native executables
- Fix outage relaunch races, finished-worker health and narrow wakes
- Judge a worker launch-failed only until its first hook
- Align the two decision records with wake withdrawal and launch-failure
- Both failing checks come from this PR's changes, and both are fixed and verified locally. 1. SonarQube quality gate. I ran the gate locally against the same SonarQube image. The reliability rating was C because Sonar found three S2259 bugs (possible null pointer): NoticeStore.wasNoticed twice and RecoveryCostStore.isCounted. Each unboxes the nullable Boolean that JdbcClient single() returns into a boolean. Invariant: an existence query gives a plain boolean and never unboxes a nullable wrapper. I fixed it at every site in this PR's store code that has the pattern: the two NoticeStore methods, RecoveryCostStore.isCounted, and EventLog.anyAfter. EventLog.anyAfter was not flagged but is written the same way. Each now uses the row-mapper idiom InboxStore already uses, `.query((row, _) -> row.getBoolean(1)).single()`. Verified: `./mvnw -Psonar verify sonar` against a local SonarQube 26.10 gives BUILD SUCCESS, QUALITY GATE PASSED and 0 open bugs or vulnerabilities, and every JVM test passes. 2. Native build and smoke test. The failing test was NativeSmokeIT.theCommandAnswersQuickly (AT-39): the p95 of 200 `edi backlog` round trips was 68 ms against a 50 ms budget. Root cause: the build runs test classes concurrently, and this PR adds NativeRecoveryIT. That test starts a second native core with tmux workers and ran alongside the latency measurement on the CI runner, competing for its processors. Invariant: the AT-39 latency measurement runs with no other native core competing for the machine. Only NativeSmokeIT measures time, so I added JUnit's @Isolated to that class. Verified: `./mvnw -Pnative verify` gives BUILD SUCCESS. NativeSmokeIT passes 13 of 13 and NativeRecoveryIT 2 of 2, with p50 20 ms and p95 23 ms. CI on the pull request remains the final check. Files changed: edi-cli/src/test/java/io/github/ythibos/edi/cli/NativeSmokeIT.java, and EventLog.java, NoticeStore.java and RecoveryCostStore.java in edi-core/src/main/java/io/github/ythibos/edi/adapter/store/
