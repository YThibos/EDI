The turn report (`edi report --turn`) becomes the session's attention list, and the overview stays with `edi sitrep` and the console's sitrep page.

The commits, in order:

- Make the turn report the captain's attention list
- Note in EDI-91 what the turn report already changed
- Carry turn items into sitrep, route blockers to turn report
- Name the turn report in EDI-92's I-21 wording
- Name the report, not the captain report, in the turn wording's refusal
- Hand the item over to the cloud session through its pull request
- Give ApiTest's workers a window no process of the machine can be, so the sitrep never reads the host's heavy runs
- Mark the item delivered
