# EDI-7 Deliver ships through the pipeline, follow their merges and clean up landed work

## What it changes

The commits, in order:

- Deliver ships: forge and pipeline adapters, done claims, edi deliver, merges, clone refresh and cleanup
- Test delivery from the domain to the native command
- Record the S5 decisions and verify gh, glab and the pipeline
- Isolate each merge watch and make edi merged idempotent
- Retry stopped clean-ups and refresh each clone on its own
- Promise a retry only where a later round retries
- Note the captain-checkout clean-up retry in the decision record
- The SonarQube quality gate failed on one condition only: software_quality_reliability_rating was 5 against a threshold of 1. I reproduced it locally against the same SonarQube image (26.10.0.133078-community), set up with ops/sonar-setup.sh. The cause is a single reliability blocker, java:S2095 at edi-core/.../adapter/pipeline/PipelineSpend.java:57. It is new in this PR. `spendQuery` prepared a statement and then bound its parameters before returning it into the caller's try-with-resources. If `setString` threw, the statement was never closed. The invariant: every JDBC statement must be owned by try-with-resources from the moment it is created. A search of edi-*/src found no other helper that creates or returns a statement this way, so this is the only place it was broken. The fix opens the statement directly in the try-with-resources header. A new `bindTheBranch` step binds the parameters, and a new `spendOf` step runs the query and reads the result in its own try-with-resources. `spendQuery` is gone; the query, the result and the empty result on SQLException are unchanged. I re-ran `./mvnw -Psonar verify` with the Sonar scan against the local server. Every test passed, including PipelineSpendTest and DeliveryStoresTest, which cover this path, and the gate reported PASSED. The other 12 open issues are maintainability findings, and the maintainability and duplication conditions were already passing. The local SonarQube container was stopped afterwards

## How it was verified
