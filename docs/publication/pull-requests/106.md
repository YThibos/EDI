# EDI-150 Pull request and merge request texts pass the publish guard before EDI posts them

## What it changes

No pull request or merge request title, description or comment that EDI or its validation pipeline posts on a forge carries a secret or personal material, so EDI-132's cleaning stays done.

The commits, in order:

- Check a request's title and description with the publish check before EDI posts or accepts it
- Pin the request text check on both posting paths and the forges, and record it in the publish guard
- Mark the item delivered

## How it was verified

The repository's build and tests, `./mvnw verify`, passed before the merge, with the native build where the change could reach the native image, and CI ran on the pull request.
