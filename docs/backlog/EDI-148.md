## Goal

EDI reads an open request's checks and mergeability in each supervision round, turns a failure or a conflict into a finding for the worker, and marks the request ready for review once its checks pass, or once verify and publish pass on a project without CI, so no long-lived monitor can be lost and nothing ever rebases.

## Context

The no-mistakes CI monitor ended with its daemon on a restart (pull request 55 and another registered project's run on 27 October 2026), rebased an open pull request when the base moved into a conflict (pull request 62), and on EDI waited on GitHub Actions jobs that never start for billing reasons (40 of 67 CI steps).
EDI-104 added `ciRuns: false` to the registry, and EDI-86 enters READY only from the forge's own view; EDI-69, a standing note that CI is unavailable, was dropped on 3 November 2026, so `ciRuns: false` is the one setting.
The captain chose EDI to mark requests ready (Q5 A).
This item adds the `Checks` stage on slice 4, the item filed from `slice-4.md`, which must have merged first.

## Before starting

- Slice 4 and EDI-86 have merged; the checks policy reads what they store and adds no other setting.

## Acceptance criteria

- `Forge` gains `checksOf(forge, address)`, read from `gh pr view` and `glab mr view` as already allowed, and `markReady(forge, address)`; `ForgeCommand` gains `gh pr ready` and `glab mr update` limited to `--ready`, and AT-03b still finds no merge argument.
- The supervision round reads the checks and mergeability of each published validation every delivery round; restarting the core while checks are pending loses nothing, and the next round reads them again.
- A failing required check or a conflict with the base reaches the worker as a `fix` finding, the conflict through the same merge-the-base steer as slice 3; nothing rebases or force-pushes.
- On a project whose CI does not run (`ciRuns: false`), the request is marked ready after `Verify` and `Publish` pass, and no CI finding is raised.
- A request is marked ready only when every required check passed at the head EDI pushed, and marking it ready feeds the READY guard of EDI-86 rather than bypassing it.
- The worker's brief no longer tells it to mark the request ready.
