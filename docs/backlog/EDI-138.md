## Goal

The worker-identity guard, the tmux guard and the `.claude` write guard refuse the bypasses found after EDI-122, EDI-123 and EDI-125 landed, the hooks cannot be redirected by local settings, and the records name plainly what a denylist still cannot contain.

## Context

EDI reviewed pull request 78 (EDI-122) and pull request 79 (EDI-123) after they merged on 28 October 2026, and pull request 81 (EDI-125, landing through pull request 83).
The review found these ways past the guards.

The worker-identity guard (EDI-122):

- `exec -c`: `CommandWrappers.java` treats `exec` as a plain wrapper, and `WorkerIdentity` never checks its `-c`, which clears the environment.
- `env` option forms: abbreviations such as `--uns` and `--ignore-env`, clustered options such as `-vu`, and values joined to `-S` or `--split-string`.
- `systemd-run --user`, and `xargs -I{} env -u {}`.
- The records overclaim: `api-access.md` and `pre-tool-guard.md` say more than the guard gives.

The tmux guard (EDI-123):

- `new-window`, `split-window` and `new-session` (`neww`, `splitw`, `new`) with a shell-command argument, and `set -g default-command`, are not treated as input in `TmuxSockets` (`INPUT_COMMANDS`), and the new window carries no `EDI_*` variables.
- tmux accepts unique prefixes shorter than four letters, so `pas`, `ru`, `sou` and `pi` pass.
- A `;` glued to an argument hides the next tmux command.
- `-S` reached through `$PWD`, through a hard link, or through `TMUX_TMPDIR`.

The hooks and the `.claude` write guard (EDI-125):

- An `env` entry in local settings, such as `PATH`, hijacks the bare `edi` hook command in the middle of a session.
- The `.claude` write guard misses paths expanded from `$`, `"$PWD/.claude/..."`, `cp -r` and `rsync` into `.`, `git checkout -- .claude`, `tar -x`, `perl -pi`, and moving `.claude` away with `mv`.
- It refuses `cp -t /tmp .claude/settings.json`, which writes nothing into `.claude`: a false positive.

Severity: medium, as for the items these findings follow up.
EDI-137 investigates the structural fix: workers that cannot reach the secrets by permission.

## Acceptance criteria

- Failing tests first reproduce each bypass listed above, and the false positive.
- `exec -c` is checked as the environment-clearing form it is.
- Every `env` option form, abbreviation, cluster and joined value that clears or unsets the worker's identity is refused.
- `systemd-run --user` and `xargs` driving `env -u` are refused.
- `new-window`, `split-window`, `new-session` with a shell command, and `set -g default-command`, count as input to the tmux server.
- Every unique prefix tmux accepts for a guarded command is recognised, not only those of four letters or more.
- A `;` glued to an argument splits the tmux commands as tmux does.
- A `-S` socket path is compared after `$PWD` and `TMUX_TMPDIR` are expanded and the real path resolved; a hard link the guard cannot recognise is named as a gap.
- The hooks call `edi` by an absolute path, and the launch check refuses `env` and `disableAllHooks` in `settings.local.json` and `settings.json`.
- The `.claude` write guard refuses a redirect or destination word holding `$`, and the copy, sync, checkout, archive, in-place edit and move forms listed above.
- `cp -t /tmp .claude/settings.json` is allowed.
- `api-access.md` and `pre-tool-guard.md` claim no more than the guards give and name the gaps that remain.
