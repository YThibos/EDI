## Goal

The weekly upkeep tells the captain when a newer JDK is possible, lists every pinned version Renovate does not manage that has a newer stable release, and Renovate's pull requests flow again without GitHub Actions minutes.

## Context

The captain's reading of the Spring Boot system requirements: Spring Boot 4.1.2 requires at least Java 17 and is compatible with versions up to and including Java 27.
So Spring Boot no longer holds EDI on the JDK 25 line; GraalVM Community Edition does, because it publishes builds on fewer JDK lines.
The captain would keep up with the newest JDK and asks for the right reminders at the moment an upgrade becomes possible.
Renovate runs from a GitHub Actions workflow, and Actions has refused every job since 22 October 2026 because of the account's billing limit, so Renovate has not run since.
The weekly upkeep is the `edi-upkeep` skill, due on Mondays through `WeeklyUpkeep` in the session-start digest.

## Acceptance criteria

1. The weekly upkeep checks whether GraalVM Community Edition has published a build on a JDK line newer than the one `mise.toml` pins, and whether the pinned Spring Boot supports that JDK.
   When both hold, it tells the captain that a JDK upgrade is possible, naming the two versions.
2. The same check covers every pinned version Renovate does not manage.
   List them from the repository: the `mise.toml` tools such as GraalVM, Node and gitleaks, the Maven wrapper's Maven version, and anything else pinned outside Renovate's managers.
   Report each one that has a newer stable release.
3. Renovate has not run since Actions stopped.
   Find a way for its pull requests to flow again without Actions minutes, present the options with their trade-offs, and ask the captain on the issue before choosing.
   Two options to weigh, not to pick between: the hosted Renovate GitHub app, which is a third-party service and the captain prefers few of those; or a Renovate run started by the weekly upkeep on the captain's machine, with its token read by an adapter at call time and never printed or stored.
4. `docs/decisions/java-toolchain-and-build.md` is corrected: Spring Boot 4.1.2 supports Java up to and including 27, so GraalVM Community Edition alone holds EDI on the JDK 25 line, and "When to revisit" follows.
5. A test pins the JDK check and the unmanaged-version check against fixed release data.
6. The upkeep reports nothing when everything is current, and names each upgrade otherwise.
7. The Renovate question is answered by the captain before any change to how Renovate runs.

## Requirements from decisions and answers

- Put the check in the weekly upkeep, and extend it to anything Renovate does not catch.
- Ask first on the item's issue about Renovate (criterion 3), with lettered options and a recommendation, and stop until the captain answers; do the other criteria in the meantime in the same pull request only if the answer does not change them, otherwise open the pull request for criteria 1, 2, 4, 5 and 6 and keep the Renovate change for a follow-up.
- Credentials are read at call time by an adapter, never printed or stored (I-32).
- Version lookups run on the captain's machine inside the weekly upkeep; the code must not need network access in its tests.
