## Goal

The weekly upkeep tells the captain when a newer JDK is possible, and lists every pinned version Renovate does not manage that has a newer stable release.

## Context

The captain's reading of the Spring Boot system requirements: Spring Boot 4.1.2 requires at least Java 17 and is compatible with versions up to and including Java 27.
So Spring Boot no longer holds EDI on the JDK 25 line; GraalVM Community Edition does, because it publishes builds on fewer JDK lines.
The captain would keep up with the newest JDK and asks for the right reminders at the moment an upgrade becomes possible.
Renovate runs from a GitHub Actions workflow; Actions refused every job from 22 October 2026 for a billing limit, and runs again since 3 November 2026.
The weekly upkeep is the `edi-upkeep` skill, due on Mondays through `WeeklyUpkeep` in the session-start digest.

## Acceptance criteria

1. The weekly upkeep checks whether GraalVM Community Edition has published a build on a JDK line newer than the one `mise.toml` pins, and whether the pinned Spring Boot supports that JDK.
   When both hold, it tells the captain that a JDK upgrade is possible, naming the two versions.
2. The same check covers every pinned version Renovate does not manage.
   List them from the repository: the `mise.toml` tools such as GraalVM, Node and gitleaks, the Maven wrapper's Maven version, and anything else pinned outside Renovate's managers.
   Report each one that has a newer stable release.
3. `docs/decisions/java-toolchain-and-build.md` is corrected: Spring Boot 4.1.2 supports Java up to and including 27, so GraalVM Community Edition alone holds EDI on the JDK 25 line, and "When to revisit" follows.
4. A test pins the JDK check and the unmanaged-version check against fixed release data.
5. The upkeep reports nothing when everything is current, and names each upgrade otherwise.

## Requirements from decisions and answers

- Put the check in the weekly upkeep, and extend it to anything Renovate does not catch.
- The captain (3 November 2026) dropped the criterion that made Renovate run without GitHub Actions: Actions runs on the repository again, and Renovate's scheduled workflow ran on 3 November 2026.
- Credentials are read at call time by an adapter, never printed or stored (I-32).
- Version lookups run on the captain's machine inside the weekly upkeep; the code must not need network access in its tests.
