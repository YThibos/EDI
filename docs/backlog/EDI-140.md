## Goal

`PinnedActionsTest` checks the pins on the parsed workflows, the SonarQube service image in CI is pinned by digest, and the mise action is given the mise version to install.

## Context

EDI-131 pinned every GitHub Action to a commit SHA and added `PinnedActionsTest` to keep it so.
The test runs line regexes over the raw workflow YAML, so a `uses:` written in another YAML form, such as a flow mapping or a quoted value, escapes it.
The `sonarqube` service in `.github/workflows/ci.yml` names its image by tag only, which its publisher can move.
Every `jdx/mise-action` step has no `version:` input, so the mise it installs is whatever is newest on the day.
Severity: informational, as for EDI-131.

## Acceptance criteria

- `PinnedActionsTest` parses each workflow and asserts the pin on every `jobs.*.steps[].uses`; only the check that the tag stands as a comment on the same line stays line-based.
- A test case shows that a `uses:` the old regexes missed is now caught.
- The `sonarqube` service image is pinned by digest, with its tag kept for readability, and the test checks that every service and container image is pinned by digest.
- Every `jdx/mise-action` step names the mise version through its `version:` input, and Renovate keeps that version and the image digest current.
- The digests and the version are verified against their sources, not guessed; a sandbox without network access says so and asks on the issue.
