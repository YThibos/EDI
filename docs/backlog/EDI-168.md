## Goal

Every job of the CI workflow passes on `main` again.

## Context

With the Actions minutes restored, the run of 2 November 2026 on `main` failed five of its six jobs for three causes, and six more showed once they were fixed.

- `TmuxClaudeRuntimeTest` expected a worker launched through `mise exec` to see no `MISE_TRUSTED_CONFIG_PATHS`, while `jdx/mise-action` sets it for the runner, and the private tmux server passes on what the test inherited; the JVM, native and SonarQube jobs ran the test and failed.
- The `npm audit` job installed only Node, so mise could not render the `JAVA_HOME` template in `mise.toml`, which names GraalVM's install path, and the job stopped before the audit.
- Once those passed, `SyntheticSecretsTest` failed on this item's own pull request: gitleaks found 4999 of the 5000 generated AWS keys in one commit; scanned again, every key gitleaks misses among many is recognised on its own, so the miss depends on where a key falls in gitleaks' input, not on the key (in a directory scan, 43 of 100,000 keys were missed, at regular intervals through the file).
- The SonarQube quality gate then failed on its reliability rating, C against the A it requires, for one finding: the host-and-port pattern of `NetworkAddresses` repeats a group by backtracking (rule S5998), so a request description holding a host of 100,000 labels overflows the stack of the publish check of request texts.
- `ProcessTableTest` then failed once in the native job: it ran `sleep` through a link named `sl) S 1 2 3`, and on the runner's Ubuntu 26.04 that process had already gone when the test read it, while the plain `sleep` processes beside it still ran; a multi-call `sleep`, as Rust coreutils ships, reads the unknown name and exits, so the test passed only when it read the process before it was reaped.
- Once a cold download could finish, Dependency-Check found what it is there to find: CVEs scored up to 8.5 in sqlite-jdbc 3.53.4.0, the store's driver, the version Spring Boot 4.1.2 manages.
- Once EDI-159 merged, the quality gate failed again on reliability: `CaptainMessageStore.nextNumberIn` unboxed the result of `query(Integer.class).single()`, which the analysis reads as possibly null (rule S2259).
- The native smoke test's proof that a command doing its work twice fails the round-trip budget failed on a fast runner: the doubled command's p95 was 49 ms, within the 50 ms limit, though its median ran 2.46 times a bare start-up's.
- A cancelled run had saved Dependency-Check's vulnerability database with its `odc.update.lock`, so every later run restored the lock, waited forty minutes for an update no process was making, failed with no data, and saved the lock again.

## Acceptance criteria

- `TmuxClaudeRuntimeTest` proves that EDI adds no trusted path of its own to a worker's launch, whatever the core inherited, and passes with and without `MISE_TRUSTED_CONFIG_PATHS` set.
- `SyntheticSecretsTest` still fails when gitleaks cannot recognise a generated key on its own, and no longer when it only misses one among the others.
- `NetworkAddresses` reads a host of any number of labels without overflowing the stack, a test shows it with 100,000, and the quality gate passes.
- `CaptainMessageStore` reads the next message number through a row mapper that yields an `int`, and the quality gate passes on the branch merged with `main`.
- `ProcessTableTest` names its oddly named process with a script of its own that waits on its input, so the test depends on no program's reading of its own name, and still fails for a parser that stops at the first `)`.
- The parent `pom.xml` overrides `sqlite-jdbc.version` with 3.54.1.0 under a Renovate regex manager, and Dependency-Check reports no finding at CVSS 7 or above.
- The doubled-command proof asserts that the budget's pace rule fails it, which holds on any machine, and [native-smoke-test](../decisions/native-smoke-test.md) says so with a history line.
- The `npm audit` job installs every tool `mise.toml` pins.
- Dependency-Check's cached database is saved only from a run that was not cancelled, a stale update lock is dropped before the scan, and the job allows a cold download to finish: five hours, since this pull request's run downloaded 79% of the NVD's 418,000 records in its 150 minutes and, cancelled at the limit, kept nothing.
- [dependency-upkeep-and-scanners](../decisions/dependency-upkeep-and-scanners.md) records the cache rule and the job's tools, with a history line.
