## Goal

A worker cannot turn its guard hooks off by writing local Claude Code settings in its own copy.

## Context

Workers may write `<worktree>/.claude/settings.local.json`, which lies inside their allowed write area.
If Claude Code lets local project settings, for example the setting that disables all hooks, override the hooks EDI passes with `--settings`, a worker can switch the guard off.
This is unverified: it has not been checked against the installed Claude Code.
Severity: medium, unverified.

## Acceptance criteria

- First verify against the Claude Code version the repository documents, with a reproduction: does a local settings file override the hooks given on the command line?
  Record the result in the Claude Code verification notes with the version it was verified on.
- If it does, refuse worker writes under `<worktree>/.claude/`, including the shell equivalents (redirects, `tee`, `cp`, `mv`, `sed -i`), and pin it with tests.
- If it does not, say so in the notes, add a test that documents the reliance, and still refuse writes to the settings files.
- A sandbox without Claude Code says plainly that the verification was not run, and asks on the issue instead of guessing.
