## Goal

Every shell snippet built from configuration or from a repository's remote validates and quotes what it interpolates.

## Context

The project build runs the configured verify command through `sh -c`, and the GitHub forge adapter interpolates the remote's host, unquoted, into a git credential-helper shell snippet.
The remote address does not validate the host, and a worker can change the shared clone's origin URL.
Severity: low.

## Acceptance criteria

- A failing test first shows a crafted remote host reaching the snippet.
- The host is validated as a DNS name before use and quoted in the snippet; a remote whose host fails is refused.
- A decision is made and recorded on whether verify commands need the same care, with the trade-off: they are the captain's own configuration, so quoting may be enough.
- Tests cover valid hosts, hosts with shell metacharacters, and an address with a port.

## Requirements from decisions and answers

- The captain (28 October 2026) asked for the findings of the read-only security review before EDI goes public to be backlogged for the cloud session.
- Reproduce first with a failing test that shows the weakness, then fix it, then record the design in `docs/decisions` (rewrite the record that covers the area in place, with a history line, or add one for a new decision).
- This item must land before the public mirror (EDI-121) is set up.
- Workers run as the same operating-system user as the primary, so a guard is a denylist and not a boundary; do not claim more than the change gives, and state what it still cannot contain.
- Tracked files, tests and records name no particular person, host, account or machine path; use invented values.
