## Goal

A wake can never be taken by a second or invisible `edi wait` of the primary: the core refuses one, and the primary's guard refuses the command before it runs.

## Context

On 2 November 2026 the primary started a second `edi wait` in the background with `&`, its output sent to `/dev/null`, chained onto an unrelated command.
That copy took a worker's needs-decision wake, printed it nowhere, and the wake was counted acknowledged when the next proper wait started.
The worker waited an hour on a question nobody saw.
A written learning already forbade starting `edi wait` with `&`; a rule the model can forget is not a safeguard.
The captain asks for hard rules that cannot be negotiated or bypassed wherever a failure would otherwise be soft or silent.

## Acceptance criteria

- The core refuses a second `edi wait` for a session while one is live, with an error that names the live one; the live one keeps its wakes.
- A wait whose live one has died (its process gone) is replaced, not refused, so a crash never locks the primary out.
- `edi wait` refuses to run when its standard output is `/dev/null` or a closed stream, before it takes any wake.
- The primary's PreToolUse guard refuses a Bash call that holds `edi wait` together with anything else: a pipe, a redirection, `&`, `;`, `&&`, `||`, `disown` or `nohup`; `edi wait` alone, run as a background command, passes.
- Every refusal says the one correct way to start the wait.
- Tests cover each refusal, the replacement of a dead wait, and the accepted form.

## Requirements from decisions and answers

- Soft and silent failures are covered by hard rules that are non-negotiable and non-bypassable: a refusal in code, not a sentence in the anchor or memory.
- Tracked tests use invented session ids.
