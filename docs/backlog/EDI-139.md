## Goal

No EDI test reaches the real Outlook calendar of the machine it runs on; every test core reads a recording fake instead, and a test pins that.

## Context

On WSL, EDI reads the captain's calendar from Outlook through `powershell.exe`.
During `./mvnw test -Pfast` on the captain's machine, `MeetingCalendar` logs "Outlook did not answer" and "Outlook is closed", so EDI's own tests call the real Outlook.
This is the same class of leak as the browser EDI-120 closed: a test reaching a program on the host instead of a fake.
`EveryTestCoreRecordsItsBrowser` replaces the captain's browser with a recording one in every test core; the calendar has no such guard yet.
Which test cores reach the calendar, and through which bean, is not recorded: the session finds that out first.
A cloud sandbox has no `powershell.exe`, so the leak may not show there; the reproduction is a test that asserts no test core runs the real calendar program, not the log line.
Severity: low.

## Acceptance criteria

- A failing test first shows that a test core reaches the real calendar adapter.
- Every test core reads a recording fake calendar in place of the real one, the way `EveryTestCoreRecordsItsBrowser` replaces the browser.
- A test fails when a test core is built that would run the real calendar program.
- `./mvnw test -Pfast` on WSL logs neither "Outlook did not answer" nor "Outlook is closed".
- The tests that check the calendar's behaviour still run against the fake, with the same coverage.

## Requirements from decisions and answers

- Tests are fast and deterministic and never reach the host's programs or the captain's data, as [test-isolation](../decisions/test-isolation.md) and EDI-120 set; rewrite that record in place with a history line if this changes it.
- Reproduce first with a failing test, then fix it.
