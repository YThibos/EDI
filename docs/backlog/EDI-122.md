## Goal

A worker can never act as the primary by leaving out its own token file, so the claim that a misled worker cannot act as the primary holds.

## Context

The command-line client falls back to the home token file when the worker's token file variable is unset.
A worker that runs `unset EDI_TOKEN_FILE` or `env -u EDI_TOKEN_FILE edi dispatch ...` in its shell therefore acts as the primary.
The shell secret guard never sees the token path in such a command, and the access record claims a misled worker cannot act as the primary.
Severity: medium.

## Acceptance criteria

- A failing test first reproduces it: a command run in a worker context with the token file variable unset reaches the core as the primary.
- The command-line client refuses the home token fallback inside a worker context, where the worker session markers are present.
- The shell guard refuses unsetting or reassigning the token file variable, in the forms `unset`, `env -u` and `export` or an inline assignment.
- Both are pinned with tests, and the access record states what it now guarantees and what it still cannot.
