## Goal

Every native build that EDI or its workers run caps its threads and heap from the machine profile, so two native builds fit side by side, and the before and after times are measured.

## Context

The captain's laptop has 4 performance cores and 8 efficiency cores (16 logical processors); WSL gets all 16 and 24 GB.
GraalVM `native-image` takes every core by default, so two native builds at once each run 16 threads and each need 6 to 8 GB.
That is how builds and the primary's wait were stopped for low memory, and why EDI hands out one native build slot at a time.
The captain's view: the constant swapping of threads and cores between builds may take longer than two builds in parallel with their own resources.
This item is held until the captain's word.

## Acceptance criteria

- Every native build EDI or its workers run caps its threads (`native-image --parallelism`, for example 8) and its heap.
- The cap comes from the machine profile, not a hard-coded number, so the desktop keeps its own.
- One build alone and two builds side by side are measured before and after, and the numbers are recorded in the pull request body.
- The one-slot rule is changed only if the measurements support it.

## Requirements from decisions and answers

- The captain (28 October 2026): queue it; "the thread fighting" between builds is the problem to settle by measurement.
- [local-native-builds](../decisions/local-native-builds.md) decided on a warning instead of a cap; this item changes that decision on measured evidence, so the record is rewritten in place with a history line.
- Machine differences come from the machine profile at runtime, never from `@Profile` or `@ConditionalOnProperty`.

## Research and measurements

- 16 logical processors, 24 GB, 6 to 8 GB per native build at full parallelism.
- `NoticeHeavyRunsAtOnce` already warns when two heavy runs overlap.

## Not for the cloud session

The measurements need the captain's laptop: the hardware, the WSL memory limit and a real two-build run.
A cloud session cannot produce them, so the item is held until the captain's word and carries the label needs-captain-machine for the measuring step.
The code for reading the cap from the machine profile can be written anywhere, but it is not to be merged without the numbers.
