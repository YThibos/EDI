## Goal

The Grep tool is guarded against the secret files the way Read is, with a designed answer for a Grep over a folder that holds a secret file.

## Context

EDI-80 guards the Read tool for workers and the primary: a Read of a file `SecretReads` names is refused as a shell's read of it is.
Grep was the recorded known gap.
This item is held until the captain's word.

## Acceptance criteria

- A Grep whose path is a secret file is refused, naming why.
- A decision on a Grep over a folder that holds a secret file is made and recorded: refuse, or allow while excluding the secret file from the search, with the trade-off stated.
- A Grep of an ordinary source file is allowed.
- The decision record that covers the guard gains the Grep case and a history line.

## Requirements from decisions and answers

- Follow-up from decision D51 (captain, 28 October 2026, "Step 6, A"): guard Grep the same way as Read, and design how a folder search is handled.
- Secrets are never read or printed by workers or the primary (I-32); the captain's word lifts the guard for the primary as it does for Read.
- A worker's `PreToolUse` matcher and the primary's must both gain `Grep`.

## Research and measurements

- The Read guard is `GuardToolCall` with `SecretReads.refusalForReading`; the matchers are in `claude/worker/settings.json` and `claude/primary/settings.json`.
