## Goal

Only the home's own token reads the list of workers and a worker's pane; a worker's token is refused, as the open-questions endpoint already does since PR 202.

## Context

The review of PR 202 fixed `GET /api/workers/questions` to require the home's token.
`GET /api/workers` and `GET /api/tasks/{reference}/peek` on main take no caller, so any worker's token can read every other worker's status and pane.
The captain asked for this to be fixed on its own.

## Acceptance criteria

- Both endpoints call the same caller check as the open-questions endpoint, so a worker's token gets 403.
- The primary, a standby session and the captain's terminal still read both.
- An API test per endpoint fails before the change and passes after.
- The supervision decision record says who may read them.

## Requirements from decisions and answers

- D92 A: the scanner remarks were accepted as traced, and the missing caller checks on main are fixed separately.
