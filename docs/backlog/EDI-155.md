## Goal

When the captain asks the primary to introspect, or the primary finds that a failure of its own cost something, one skill takes it from evidence to backlogged hard rules, with the evidence gathered by a script so the routine costs few tokens.

## Context

On 2 November 2026 the captain asked the primary to introspect after a worker's question went unseen for an hour.
The investigation followed a fixed shape: rebuild the timeline from the store rather than from memory, separate the model's slip from the system gap that let it cost anything, turn each soft or silent failure into a refusal in code, and backlog the fixes with the `edi-backlog-item` skill.
Done by hand, the evidence gathering read the store's tables, the worker's pane, the task timelines and the validation pipeline's database through several ad hoc commands; the captain asks for this routine to be scripted and reusable for token efficiency.
The captain uses the word "introspect" for this: the primary checks its own workings and comes up with a solution to backlog.

## Acceptance criteria

- A skill `introspect` in `claude/skills/introspect/` triggers when the captain says introspect, or asks why something of the primary's own went wrong and how to prevent it.
- Its script `introspect.mjs` beside it takes a time window and optionally a task, a worker, a wake number or a decision number, and prints one compact timeline: wakes raised, delivered, to which session and when acknowledged; worker states and status texts; steers with the keys they resolve and when they were acknowledged; decisions raised and answered; hook and guard refusals; validation pipeline runs and steps for the task's branch; presence changes.
- The script flags the usual soft failures by itself: a wake acknowledged with no matching action afterwards, a needs-decision key left without a resolving steer for longer than a threshold, two waits overlapping in one session, a report stating nothing waits while a worker waits, a gate parked longer than a threshold.
- The script reads the store read-only, never prints a secret, and keeps its output under a set size by default, with a flag for the full detail.
- The skill's steps: run the script; name the cause chain in two parts, the model's slip and the system gap; for every soft or silent failure, write a hard rule as a refusal or invariant in code, with a memory learning only as the interim until it lands; draft one backlog item per rule and hand the drafts to `edi-backlog-item` in one batch; tell the captain the cause, the interim rule and the backlogged items with their addresses.
- The script can write the backlog drafts' skeletons (fields filled, the Context filled from the timeline, the other sections left for the primary), so the skill only writes the reasoning.
- The anchor's skill list names `introspect`.
- Tests cover the script's timeline and each flag, on an invented store.

## Requirements from decisions and answers

- Soft and silent failures are covered by hard rules that are non-negotiable and non-bypassable: the skill never ends with only a sentence in memory or the anchor.
- EDI work goes to the upstream backlog through `edi-backlog-item`; the skill reuses it rather than repeating its steps.
- Routine procedures are scripted for token efficiency; the skill holds only the judgement.
- Tracked tests and examples use invented ids, keys and sessions.
