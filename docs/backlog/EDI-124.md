## Goal

The shell secret guard recognises a secret file by the path it resolves to, not by the literal text of a word, and covers the tools that bypass the shell.

## Context

The guard checks that a word ends with the token file's name, so `cat ~/.edi/state/core.tok*`, a doubled or dotted path segment, a symlink to the state directory and `python3 -c` with a built string all pass.
The documentation admits only the directory change and the variable cases.
The worker's tool matcher also leaves out Glob and the connector tools; Grep is covered by EDI-113.
Severity: medium.

## Acceptance criteria

- Failing tests first reproduce each bypass listed above.
- Candidate paths are normalised and glob-expanded, and real paths are resolved, before they are compared with the secret files.
- Glob is covered by the worker's tool matcher and refused for the secret files.
- The guard record states plainly that a denylist cannot fully contain an agent running as the same user, and sets out the stronger options for the captain to weigh: workers as another operating-system user, or tokens that grant no primary rights.
- The captain's choice among those options is asked on the issue with lettered options and a recommendation, and is not made by the session.

## Requirements from decisions and answers

- The captain (28 October 2026) asked for the findings of the read-only security review before EDI goes public to be backlogged for the cloud session.
- Reproduce first with a failing test that shows the weakness, then fix it, then record the design in `docs/decisions` (rewrite the record that covers the area in place, with a history line, or add one for a new decision).
- This item must land before EDI-132 makes the repository public.
- Workers run as the same operating-system user as the primary, so a guard is a denylist and not a boundary; do not claim more than the change gives, and state what it still cannot contain.
- Tracked files, tests and records name no particular person, host, account or machine path; use invented values.
