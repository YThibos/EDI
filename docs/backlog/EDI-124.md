## Goal

The shell secret guard recognises a secret file by the path it resolves to, not by the literal text of a word, and covers the tools that bypass the shell.

## Context

The guard checks that a word ends with the token file's name, so `cat ~/.edi/state/core.tok*`, a doubled or dotted path segment, a symlink to the state directory and `python3 -c` with a built string all pass.
The documentation admits only the directory change and the variable cases.
The worker's tool matcher also leaves out Glob and the connector tools; Grep is covered by EDI-113.
Severity: medium.

## Acceptance criteria

- Failing tests first reproduce each bypass listed above.
- Candidate paths are normalised and glob-expanded, and real paths are resolved, before they are compared with the secret files.
- Glob is covered by the worker's tool matcher and refused for the secret files.
- The guard record states plainly that a denylist cannot fully contain an agent running as the same user, and sets out the stronger options for the captain to weigh: workers as another operating-system user, or tokens that grant no primary rights.
- The captain's choice among those options is asked on the issue with lettered options and a recommendation, and is not made by the session.

## Handover

Work in progress is on branch `feature/EDI-124` in the draft pull request https://github.com/YThibos/EDI/pull/80; continue there, and read its body first.
The body says where the work stands, what is verified with which command, what is left, and the open question with its options.
The captain's answers so far: question 1 A and question 2 A on the pull request; "1A 2A" on the review of 29 October 2026; and A on the review finding about the extra expansion forms.

Ask the captain this open question first, from review finding `zsh-blank-group-still-fails-open`.
zsh reads a group attached to a word as part of the word even when it holds a blank, so `cat <state>/core.(tok|x y)en` reads the home token, and a glob qualifier runs code, so `ls *(e:git push --no-verify:)` runs the push; the guard reads both as a subshell and lets them through.

- A. Read a group attached to a word as part of the word even when it holds blanks, its inside also read as commands, except an empty `()` (a function definition) and a group after `=` (an array); and refuse as unreadable any glob group that holds zsh's code-running qualifiers `e(...)` or `+cmd`.
  bash rejects an attached group with blanks as a syntax error, so this costs nothing under bash.
  Recommended.
- B. Name zsh's blank groups and its code-running glob qualifiers as gaps in the record, with tests pinning them, and backlog pinning the workers' shell to bash.
- C. Both A and the backlog item from B.

Then fix these two review findings, each reproduced first by a failing test:

- `function-definition-hides-its-body`: the empty `()` of a function definition, as in `push() { git push --no-verify; }; push`, is read as a glob group, so the body's first command escapes the program-name rules; an empty group is never a glob group.
- `bundled-short-options-skip-path-lookup`: `curl -sd@<state>/./core.token` and `curl -sT<state>//core.token` are not looked up, since only the first option letter is stripped; look past bundled short option letters too.

Then verify locally, run the no-mistakes pipeline to a clean pass, mark this item delivered, and mark the pull request ready for review.
