## Goal

A workaround whose ticket is an EDI backlog item reads as ticketed whether or not the item has a local task, `edi memory stow-list` still answers when the registry cannot be read, and a workaround's ticket is found wherever its entry names it.

## Context

EDI-81 made learnings name their ticket; its pull request 76 was merged with option A of its review, and EDI's local review of it found three gaps.

- An EDI-native key resolves only through the task store, in `WorkaroundTickets.java`.
  A backlog item with no task row, such as one delivered by a cloud session or one still open in `docs/backlog`, reads as "unticketed" although its ticket exists.
- `stow-list` fails when the registry cannot be read, because `registry.entries()` is called unguarded there, unlike on the session-start digest's path.
- `UNTIL_KEY` needs the key at the very end of the entry, so "until `EDI-69`" with the key in backticks, or an entry with an evidence line beneath it, hides the workaround.

What option A of pull request 76 chose is not in the notes: the session reads the pull request's review first, and does not undo that choice.

## Acceptance criteria

- Failing tests first reproduce each of the three gaps.
- An EDI-native key resolves against the task store and against the items in `docs/backlog`, so an item with no task row reads as ticketed.
- `edi memory stow-list` answers with the entries it can read and says the registry could not be read, instead of failing, as the digest does.
- A workaround's ticket is found when the key stands in backticks or is followed by more text or by an evidence line.
- A key that names neither a task nor a backlog item still reads as unticketed.
