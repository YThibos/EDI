## Goal

A ship that adds a new Maven module can report done when the only SNAPSHOT line it adds is the module's parent reference to its own reactor's version.

## Context

On 2 November 2026 a merge request of another registered project added a module whose pom names its parent as `0.1.0-SNAPSHOT`, as every sibling module does, because a child must name its parent's version and the release jobs rewrite all modules together.
The captain answered D82 A: a module's parent reference to its own reactor's SNAPSHOT version is not a SNAPSHOT dependency and is allowed.
`SnapshotVersions` still refused the worker's done (naming the new module's `pom.xml`, line 10), and nothing in EDI could record the exception, so the done could not be reported.

## Acceptance criteria

- `SnapshotVersions` does not report a SNAPSHOT version that sits in a `<parent>` element whose groupId and artifactId are those of a pom in the same repository and whose version equals that pom's own version.
- Every other SNAPSHOT version in a build file is still refused: a dependency, a plugin, a parent outside the repository, and a parent version that differs from the reactor's.
- The publish check follows the same rule.
- Tests cover each accepted and each refused case.

## Requirements from decisions and answers

- D82 A: a module's parent reference to its own reactor's SNAPSHOT version is allowed, like every sibling module.
- No SNAPSHOT version reaches a remote otherwise.

## Read first

## How to verify

- `./mvnw verify`, then the native quick build and its smoke test.
- By hand: a branch adding a module with a reactor parent reports done; a branch adding a SNAPSHOT dependency is refused.
