## Goal

Every open or held item in `docs/backlog` that has no GitHub issue yet gets one, as the backlog's index describes, and the index names each issue's number.

## Context

EDI-135 brought the backlog up to date and was meant to open the items' issues as well.
Its worker was retired when pull request 77 merged on 28 October 2026, before it opened any issue.
The index's Issue column therefore still shows `-` for the items that existed then.
Items added since with the `edi-backlog-item` skill get their issue from the skill, together with the pull request that adds them, so some rows may already name an issue; those are left as they are.
Until an item has its issue, an open pull request or a pushed branch for it is its claim, as the pickup protocol says.

## Acceptance criteria

- Every item in the index whose status is open, held, parked or needs-captain-machine, and whose Issue column shows `-`, has exactly one GitHub issue.
- Each issue follows the README's Issues section: the title is `EDI-<n> <the item's title>`; the body is a short line linking the item's file on `main` and the blockers as issue references, and nothing else; the labels are the wave (`wave-1` to `wave-6`, or `security` for the security section), `cloud-ok` or `needs-captain-machine`, and `parked` where the item is held or parked.
- A missing label is created with the same name the `edi-backlog-item` skill uses.
- An item already claimed by a draft pull request has its issue linked to that pull request, and the pull request's body says `Closes #<issue>`.
- The index names each new issue's number in its row, in one small pull request that changes no other column and no item's file.
- No issue is opened twice: an issue that already carries an item's title is reused.
- Delivered items get no issue.

## Requirements from decisions and answers

- The captain (28 October 2026) set this work aside for his cloud session, or for his machine on his word.
- The issues copy no criteria: each item's file stays the only source of truth, as the README says.
- Blockers in an issue body are issue references, so an item's issues are opened after the issues of its blockers, or its body is updated once they exist.
- Tracked files, issues and pull requests name no particular person, host, account or machine path.

## How to verify

- List the repository's issues and compare them with the index: every open, held, parked or needs-captain-machine row names an issue, each issue's title, body and labels follow the Issues section, and no item has two issues.
- Open each issue's link to its item's file once the pull request has merged.
- `./mvnw verify` still passes; the change touches only `docs/backlog/README.md` and any pull request bodies.

## Delivery

Deliver this item as the [pickup protocol](README.md#pickup-protocol) says: a draft pull request that names the item and closes its issue, local verification in the pull request body, a question with lettered options instead of a guess, and this file's status and the index row updated in the same pull request.
