## Goal

The worker answers each finding in its own session, fixing it on top of its commits or dismissing it with a reason the reviewer reads, the next review reads only what changed, and a branch behind its base is merged up to it, never rebased.

## Context

Today every review fix is a cold fix agent (85 calls, 26.8M weighted tokens), although the worker already chooses which findings get fixed: `auto_fix.review` is 0 in the pipeline's configuration.
The rebase step rewrote two ships' commits and stranded them on 27 October 2026; EDI-104 now skips it and has the worker merge the base, and EDI-67 steers every delivered task to merge the base after a merge lands.
The captain chose the worker as the fixer (Q2 A) on the condition that it stays safe and unbiased.
This item builds on slice 2, the item filed from `slice-2.md`, which must have merged first.

## Before starting

- Slice 2 has merged, and EDI-67 has merged, since `BaseSync` reuses its base-moved steer.

## Acceptance criteria

- `edi validation answer <stage> --fixed <ids>` after the worker's fix commits, or `--dismiss <ids> --why "<reason>"`, records the answer; a dismissal without a reason is refused.
- After a fix, the next validation re-reviews only the range from the last approved head, its round count rises by one, and approvals of stages the delta cannot affect are kept.
- The next review round is given every dismissal with its reason; a finding the reviewer raises again after a dismissal becomes an `ask-captain` decision, never a second dismissal.
- The `BaseSync` stage checks whether `origin/<base>` is an ancestor of the head; when it is not, the worker gets one finding to merge `origin/<base>` with a merge commit whose subject starts with the work key, through the same steer EDI-67 sends after a merge, never a second one.
- No code path in EDI runs `git rebase`, `git commit --amend` on a submitted commit or a force-push: a rule in `ArchitectureRulesTest` on `adapter.git`'s calls.
- Each validation's head descends from the previous one's (slice 1's guard), so no fix or merge drops a commit.
