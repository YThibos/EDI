## Goal

Delivering a backlog item edits only that item's own file, so two open pull requests never conflict in `docs/backlog/README.md`.

## Context

The index carried a Status and an Issue column, and every delivery set its own row to `delivered` in the same pull request.
Rows sit next to each other, so each merge to `main` left almost every open pull request in conflict on the index, and some pull requests changed dozens of rows at once.
The captain chose option A: each item file becomes the only place for its status and its issue, and the index keeps only what rarely changes.

## Acceptance criteria

- Every index table holds only the order, the item, the title, the size, the severity in the security section, and the blockers.
- Every item file carries `Status` and `Issue` in its header; an item without an issue carries `-`.
- `node docs/backlog/board.mjs` prints the index with each item's status and issue read from the item files, and `--next` lists the open items whose blockers are all delivered.
- A test holds the index and the item files to each other: every row has its file, every file has exactly one row, no index table carries a status or an issue, and every file has one status and one issue.
- The pickup protocol, the `edi-backlog-item` skill and its script, each item's Delivery section and the `backlog-in-the-repository` record say that a delivery edits only its own file.
- The script names a new item's issue in its file, not in its index row.

## Requirements from decisions and answers

- The captain (4 November 2026) chose option A: status and issue only in the item file, a script for the live view, a test for consistency.
- The index order rule stays: a new item takes the highest order plus one across `main` and every branch awaiting merge.

Deliver this item as the [pickup protocol](README.md#pickup-protocol) says: a draft pull request that names the item and closes its issue, local verification in the pull request body, a question with lettered options instead of a guess, and this file's status updated in the same pull request.
