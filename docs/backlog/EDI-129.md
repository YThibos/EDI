## Goal

The EDI home is created owner-only, its files too, and an existing home is repaired when the core starts.

## Context

The store, the ledger and the state files are created world-readable.
They hold only token digests, but also decisions and task texts.
Severity: low.

## Acceptance criteria

- A failing test first shows a created home or file with group or other permissions.
- The EDI home is created with mode 0700 and its files with 0600, or the core runs with umask 077.
- On start, the permissions of an existing home are repaired and the repair is reported once.
- The tests use a temporary home and skip with a reason on a filesystem without POSIX permissions.

## Requirements from decisions and answers

- The captain (28 October 2026) asked for the findings of the read-only security review before EDI goes public to be backlogged for the cloud session.
- Reproduce first with a failing test that shows the weakness, then fix it, then record the design in `docs/decisions` (rewrite the record that covers the area in place, with a history line, or add one for a new decision).
- This item must land before EDI-132 makes the repository public.
- Workers run as the same operating-system user as the primary, so a guard is a denylist and not a boundary; do not claim more than the change gives, and state what it still cannot contain.
- Tracked files, tests and records name no particular person, host, account or machine path; use invented values.
