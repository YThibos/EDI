## Goal

Adopting a task from the old harness strips its leading "KEY KIND:" prefix from the title, and existing adopted tasks are migrated.

## Context

EDI-82's test step saw a task adopted from the old harness listed in the console under a title that kept the old prefix, a work key then a kind word and a colon, while the console already shows the kind.
This item is held until the captain's word.

## Acceptance criteria

- Adoption strips a leading "<KEY> <KIND>:" prefix from the title.
- Existing adopted tasks are migrated by a Flyway migration.
- Tests cover both: a new adoption, and the migration of an already adopted task.
- A title without that prefix is left alone.

## Requirements from decisions and answers

- Below version 1.0.0 nothing legacy lingers: no shim that keeps reading the old title shape.
- Tracked tests use invented keys and titles.

## Research and measurements

- The kind is already shown by the console, so the prefix duplicates it.
