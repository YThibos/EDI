## Goal

Each project moves from no-mistakes to EDI's own validation once its shadow deliveries show EDI's review misses nothing the captain wanted, EDI first, and once every project has moved, the no-mistakes adapter, its port and the configuration EDI writes into it are removed.

## Context

Slices 1 to 5 build EDI's validation beside no-mistakes, which stays the pipeline of record so that a broken validation of EDI's own can never approve its own fix.
A registered project's no-mistakes test agent does real end-to-end work, starting the backend against a throwaway database, which a verify command cannot replace; the captain chose to keep such an agent only on projects that opt in (Q3 A).
This item builds on slice 5, the item filed from `slice-5.md`, which must have merged first.

## Before starting

- Slices 1 to 5 have merged and have run in shadow beside no-mistakes on at least ten EDI deliveries.

## Acceptance criteria

- The registry gains a per-project `validation` setting, `edi` or `no-mistakes`, and the brief follows it: `edi validate` and its inbox messages for `edi`, the no-mistakes call of [pipeline-steps](../decisions/pipeline-steps.md) for `no-mistakes`.
- A project that opts in gets an end-to-end test session in `Verify`, launched like the reviewer of slice 2 and told to exercise the change against a throwaway environment, whose findings join the validation's.
- The cut-over pull request records the shadow comparison over at least ten EDI deliveries: no finding no-mistakes raised that EDI's review missed and the captain later wanted.
- It also records every finding the worker dismissed that no-mistakes' fix agent would have fixed and the captain later wanted; if there is any, the cut-over waits and Q2 goes before the captain again with option B, a fresh fix agent.
- EDI moves first; each other project moves after five deliveries on `edi` with no fallback to no-mistakes.
- Once every project is on `edi`: `NoMistakesPipeline`, `AgentArguments`, `CommitKeys`, `PipelineConfiguration`, `AxiStatus`, `PipelineSpend`, `PipelineReviews`, `Program.NO_MISTAKES`, the `Pipeline` port, `ObservePipelines`' no-mistakes reading and their tests are removed, and the EDI repository's `.no-mistakes.yaml` goes once `.edi/review.md` holds its rules.
- `docs/decisions/pipeline-agent.md`, `pipeline-commit-keys.md`, `pipeline-steps.md`, `supervision.md` and `ports-and-architecture-rules.md` are rewritten in place with history lines, `docs/verification/no-mistakes.md` is retired, and `PortInventoryTest` counts five ports under the updated record.
- No tracked file outside the decision history names no-mistakes.

## Requirements from decisions and answers

- D47 A (the captain, 29 October 2026): cut over one project at a time after a shadow period, then remove no-mistakes.
- Q3 A: verify commands everywhere, plus an end-to-end agent on projects that opt in.
- Q2 A, with the captain's condition: if a better review would come from an independent fixer, he leans to B; the shadow comparison is what decides, and any finding the worker wrongly dismissed puts Q2 before him again.
- A seventh port needs a recorded decision; removing one changes [ports-and-architecture-rules](../decisions/ports-and-architecture-rules.md) and `PortInventoryTest` in the same pull request.

## Research and measurements

- Estimated running cost on the full design: about 123M weighted tokens per 93 runs against 236M today, about 48% less; the shadow period measures the real figure, which the pull request records.
