## Goal

The EDI repository itself becomes public, as clean as possible of every personal and employer trace, with the right security settings and an Apache-2.0 licence.

## Context

The captain backed off from a separate public mirror: it was always his goal to make this repository public, and Actions being free on a public repository settled it.
He authorises a revised history on a new default branch for this task, and the new branch becomes the default while the old `main` is deleted.
The act itself (switching the default branch, deleting `main`, deleting runs, editing pull request texts) still needs his word in the session that does it.
Rewriting history never means a force-push: the revised history is pushed as a new branch.
A review on 28 October 2026 found, in the code and the full history, no secret in any commit (the secret scanner, over every reference), and the traces listed below.

## Findings to clean

1. History:
   - seven early commits carry the captain's personal address as author;
   - a registered work project's example ticket keys sit in the branch-name test and in the no-mistakes verification note;
   - revise on a new branch, with the authors on the platform's no-reply address and neutral example keys, make it the default branch, delete the old `main`, and never force-push.
2. Pull request descriptions:
   - about 20 of the 72 hold an employer's internal hostnames, an internal proxy address and port, the captain's work username, source-control group and ticket names, home paths and quoted captain words, the worst being numbers 1, 13, 28, 33, 45, 62, 64 and 68;
   - edit each, then delete the old revisions from each edit history;
   - scan every title, body, review comment and the dependency dashboard issue with the same patterns before and after.
3. Pull request refs:
   - every pull request keeps its ref pointing at its commits even after a history rewrite;
   - scan those 72 refs with the secret scanner and the personal-detail patterns;
   - whatever cannot be cleaned there needs a support request to the platform to purge unreachable objects and cached views, and is listed for the captain.
4. Actions:
   - delete every workflow run, with its logs, and all 65 artefacts;
   - check the workflows for anything that publishes on a public repository.
5. Branches: delete the stale ones.
6. Public settings:
   - secret scanning with push protection, dependency alerts, private vulnerability reporting with a `SECURITY.md`;
   - the default token read-only, approval for first-time contributors' workflows, actions pinned to commit SHAs ([EDI-131](EDI-131.md));
   - branch protection on the default branch;
   - a `LICENSE`, Apache-2.0.

## Acceptance criteria

- A checklist in `docs`, with no personal details, covers every finding above and records what was done.
- A final report to the captain says what was cleaned, what the platform's support must purge, and the exact switch-to-public step, which the captain performs himself.
- The revised history holds no personal author address and no work-project key, and the secret scanner and the publish check pass over all of it.
- Every pull request text, review comment and issue passes the same patterns, before and after the edits.
- The workflow runs and artefacts are gone, and the workflows are safe to run on a public repository.
- The public settings above are on, and `LICENSE` holds Apache-2.0.

## Not for a cloud session

Switching the default branch, deleting `main`, deleting runs and artefacts, editing pull request texts, the settings on the captain's account and the support request need that account and the captain's word in the session that does them.
A cloud session may prepare the checklist, the `LICENSE` and the `SECURITY.md` in a pull request once the item is released.
