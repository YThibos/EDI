## Goal

The EDI repository itself becomes public, as clean as possible of every personal and employer trace, with the right security settings and an Apache-2.0 licence.

## Context

The captain backed off from a separate public mirror: it was always his goal to make this repository public, and Actions being free on a public repository settled it.
A review on 28 October 2026 found, in the code and the full history, no secret in any commit (the secret scanner, over every reference), and the traces listed below.
A second review on 29 October 2026 measured them by kind, and the captain decided what is critical:

- The commit history keeps its commits as they are: it holds three early commits authored with the captain's personal address, example ticket keys of a registered work project in tests, and the name of the keys file as a test literal, and the captain judged none of that critical enough to rewrite (29 October 2026).
- The pull request descriptions are critical: several carry an employer's internal proxy address and port, internal hostnames, the captain's work username, home paths, source-control group and project names and work ticket keys, and the captain wants every description fixed, not only those that match.
- No history is rewritten, no new default branch is made and `main` stays the default branch.
- The acts on the captain's account (editing pull request texts, deleting their old revisions, deleting runs, the settings) still need his word in the session that does them.

## Findings to clean

1. History: kept as it is, on the captain's word of 29 October 2026; nothing to do.
2. Pull request descriptions, the critical finding:
   - every pull request's title and description is reviewed and rewritten, not only the 17 of 87 that matched on 29 October 2026, so that none names an internal hostname, IP address, proxy, port, username, account, home path, source-control group or project, work ticket key or employer, and none quotes the captain's words beyond what the change needs;
   - the 29 October review found, in 17 descriptions: an internal proxy address with its port (7 descriptions), hostnames under two internal domains (8), the captain's work username (15), home paths (7), source-control group and project names (6), work ticket keys (10), the keys file's name and the captain's full name (1 each);
   - rewrite each as a neutral summary of what the change does and how it was verified;
   - then delete every older revision from each description's edit history, since the platform keeps them visible; the platform's API cannot do that, so it is done in the web interface, on the captain's account;
   - scan every title, body, review comment, review and the dependency dashboard issue with the same patterns before and after.
3. Pull request refs:
   - with no history rewrite, every pull request ref points at commits already on `main` or on its branch, which the history decision covers;
   - scan the 72 or more refs with the secret scanner, and list anything outside the kept history for the captain.
4. Actions:
   - delete every workflow run, with its logs, and every artefact; a sample on 29 October 2026 found no personal or network detail in the run titles (all of them) or in seven logs, but the 55 dependency-check reports map old vulnerabilities and the rest was not read;
   - check the workflows for anything that publishes on a public repository.
5. Branches: delete the stale ones.
6. Public settings:
   - secret scanning with push protection, dependency alerts, private vulnerability reporting with a `SECURITY.md`;
   - the default token read-only, approval for first-time contributors' workflows, actions pinned to commit SHAs ([EDI-131](EDI-131.md));
   - branch protection on `main`;
   - a `LICENSE`, Apache-2.0.

## Acceptance criteria

- A checklist in `docs`, with no personal details, covers every finding above and records what was done.
- A final report to the captain says what was cleaned, what the platform's support must purge, and the exact switch-to-public step, which the captain performs himself.
- Every pull request title, description, review comment and review, and every issue, passes the patterns after the edits, and no description keeps an older revision in its edit history.
- The secret scanner and the publish check pass over the current tree; the kept history is recorded in the checklist as the captain's decision.
- The workflow runs and artefacts are gone, and the workflows are safe to run on a public repository.
- The public settings above are on, and `LICENSE` holds Apache-2.0.
