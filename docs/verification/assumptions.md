# The specification's assumptions, verified

Section 3.3 of EDI's rewrite specification lists the assumptions EDI is built on.
Slice S0 verified each one on the laptop on 15/10/2026; the desktop was not reachable from that machine.
An assumption that could not be verified was raised as a decision; the answers are recorded below.

| # | Assumption | Outcome | Evidence |
|---|---|---|---|
| 1 | Both machines run WSL2 Ubuntu with systemd, so a user service can run the core. | Verified on the laptop; the desktop is verified at its bring-up in slice S11, as decided. | WSL2 kernel 6.18, Ubuntu 24.04.5 LTS; process 1 is `systemd`, `/etc/wsl.conf` sets `[boot] systemd=true`, and `systemctl is-system-running` answers `running`. |
| 2 | Java 27 as GraalVM Community Edition, and Maven 3.9 or later, through mise on both machines; fall back to Java 25 only if no native toolchain exists for 27, and say so. | Not met for Java 27; the specification's fallback applies ([java-toolchain-and-build](../decisions/java-toolchain-and-build.md)) and was confirmed. Maven verified; the desktop is verified in slice S11. | JDK 27 is generally available since 15/09/2026, but on 27/10/2026 no GraalVM Community build exists on it: the newest is GraalVM Community 25 Innovation 4 (graal 25.4.4.1.1, JDK 25.0.4.1.1), and the release calendar plans only 25.x releases through February 2027. Spring Boot 4.1.1 supports Java up to 26, and mise's `java` plugin lists `graalvm-community` up to 25.0.2. EDI pins GraalVM Community 25.4.4.1.1 through mise's `http` backend and Maven 4.0.0-rc-7 through the wrapper. |
| 3 | Claude Code keeps its hook events, flags and JSON hook input. | Verified on Claude Code 2.1.300. | [claude-code.md](claude-code.md). |
| 4 | The validation pipeline stays an external tool with `axi run`, `axi respond` and `axi status --run`, opening draft merge requests on GitLab and draft pull requests on GitHub. | Verified on version 1.84.0. | The three commands exist with those flags. Drafts are configuration: `providers.github.draft_pull_requests: true` in this repository's `.no-mistakes.yaml` makes this slice's own pull request a draft. |
| 5 | The research-board tool stays external, and the sitrep board moves into the EDI console. | Verified. | The board tool's command answers with version 0.1.88; the console module exists ([console](../decisions/console.md)). |
| 6 | The time-booking tool stays the only owner of worklog booking. | Not verifiable by a machine check; confirmed by the captain's settled decision on time booking (E7). | EDI contains no booking code and only emits the activity ledger in a later slice. |
| 7 | The EDI repository is private, owned by the captain's GitHub account, and holds no personal or employer data. | Verified, after a decision on commit identities. | `gh` reports the repository as private on the expected account. A scan of every tracked file for the laptop's employer names, hosts, account names and home paths finds nothing. Commit identities came from the laptop's work configuration; as decided, the EDI clone now commits under the captain's GitHub no-reply address, and every commit on `main` and on this slice's branch carries it. |
| 8 | The Java namespace `io.github.ythibos.edi` and the Maven group `io.github.ythibos`, which the captain may replace in S0. | Verified and kept. | The GitHub account that owns the repository is the namespace's basis ([java-toolchain-and-build](../decisions/java-toolchain-and-build.md)). |
| 9 | No second captain, no machine beyond the two, and no state shared between the machines' EDI homes except the repository. | Not verifiable by a machine check; confirmed by the captain's settled decision on two machines with separate personal configuration (E8). | Nothing in S0 shares state between homes. |
